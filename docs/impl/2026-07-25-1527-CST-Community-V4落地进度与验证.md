# Community V4 落地进度与验证

V4 机制的状态层随提交 09a92b5 入库，五个领域模型、服务方法、对外 API、测试周期与持久化 section 齐备，玩家侧菜单与消息为零。本文先给出总体进度、机制差距与版本划分，随后逐版本展开菜单设计、后端接线、逻辑检修与验证步骤。全部设计以仓库现有代码为基线，行号引用与签名摘自当前源码。

## 总体进度

已入库的部分覆盖后端闭环。状态模型 `CommunityV4State.kt` 提供建设奖励台账、地皮、称号、政策、税收福利结算五个数据类，`Community.kt:26-31` 持有对应持久化字段。`CommunityV4Service` 提供九个服务方法，`CommunityApi` 暴露十个带线程校验与快照回滚的入口。`CommunityDatabase` 以 `SECTION_V4_STATE = 5` 独立 section 持久化 V4 字段，旧库缺少对应 section 时按默认值加载。测试侧六组单测覆盖服务幂等、回滚顺序、测试周期隔离与 V4 section 序列化往返。GM 命令 `/community v4 summary|settle|test start|test status` 可驱动结算与测试周期。

未入库的部分集中在玩家触达面。五个机制没有任何菜单，税收福利与政策仅有 GM 命令，普通玩家无法领取建设奖励、交易地皮、购买称号或查看政策。代码审查同时发现六处逻辑缺陷，按版本分配修复。

| 编号 | 缺陷 | 证据 | 归属版本 |
| --- | --- | --- | --- |
| D1 | 建设奖励入账方向颠倒，`claimBuildingReward` 把奖励记为 `communityIncome`，玩家账户不变 | `CommunityV4Service.kt:25` | V4.2 |
| D2 | `buyTitle` 无扣款路径，`TITLE_SLOT_COST` 配置无引用 | `CommunityV4Service.kt:71` | V4.4 |
| D3 | `applyDuePolicy` 无生产调用方，政策 pending 永不生效 | `CommunityV4Service.kt:89` | V4.5 |
| D4 | 税收福利结算无生产触发器，仅有 GM 命令与测试周期 | `CommunityV4Service.kt:116` | V4.5 |
| D5 | 四个国库流水 desc key 在语言文件中缺失，账本回退显示原始 key | `zh_cn.json`、`en_us.json` | V4.2、V4.5 |
| D6 | `saveMutation` 快照为浅拷贝，集合内对象原地变更不可回滚 | `CommunityApi.kt:201-227` | V4.0 |

与设计文档的机制差距需要明确取舍。建设奖励在现有代码中是玩家主动领取制，限额取 `BUILDING_REWARD_DEFAULT_BLOCK_LIMIT` 默认 12，单价取 `BUILDING_REWARD_BLOCK_VALUE`，设计文档的小时自动结算、周上限与国库分成均未实现。税收福利在现有代码中是国库资产乘以 `TAX_WELFARE_TAX_RATE` 加人均固定福利，设计文档的六政策组合、收入条件与保护线均未实现。地价在现有代码中是面积乘以系数加国库权重，设计文档的栖息时间加权未实现。发展度在 `snapshotDevelopment` 中走对数合成公式，与设计文档的平方根公式不同。V4 落地以现有代码机制为准完成玩家触达，差距项不阻断菜单落地，是否补齐机制属于后续版本决策。

逻辑检修覆盖六点。重复挂牌由 `salePrice` 状态机挡住，已挂牌地皮的重复挂牌走改价分支。购买与取消挂牌并发时，pending 归属校验保证买卖双方角色正确，价格以 pending 登记时的快照为准，改价后旧 pending 失效。共有删除在对方超时未确认后 pending 过期，发起方聊天收到超时提示。成交后原所有者权限清除，属于社区管理人员的原所有者保留权限，与设计文档一致。WorldGeo 侧 SubSpace 写入失败时走 `runCommunityMutationOrRollback`，社区记录回滚并提示操作者。`saleDisabled` 切换即时生效，市场列表打开时读取最新状态。

验证步骤如下。

1. 挂牌后地皮出现在市场列表，购买者确认后 Economy 账户与国库流水同步变动。
2. 共有地皮删除在对方五分钟内确认后生效，超时后确认按钮提示过期。
3. 扩建申请进入审批列表，管理者批准后范围生效。
4. OP 标记禁止交易后地皮从市场消失且无法挂牌。

## V4.5 政策与税收福利

D3 与 D4 修复先行。新增周期推进服务，经 WorldGeo 时间服务 API 订阅自然周周期，周期到达时遍历社区执行 `applyDuePolicy` 与 `freezeTaxWelfare` 加 `applyTaxWelfare`。推进器携带周期标识，重启后按周期标识幂等补算，结算记录 `periodId` 唯一挡住重复结算。D5 的 `policy_switch`、`tax`、`welfare` 三个键随本版本补入语言文件。

| 页面 | 槽位 | 内容 |
| --- | --- | --- |

| 社区汇总页 | 10 GOLD_BLOCK、12 REDSTONE、14 SUNFLOWER、16 BARRIER | 国库余额、预计总征税、预计总福利、余额保护线，管理者可见 |
| 政策选择页 | 10 至 15 六个政策物品 | lore 展示启用项、切换成本、冷却与生效周期，点击进确认页 |
| 结算历史页 | 列表内容区 | 每条结算展示周期、税额、福利、状态与失败原因，FAILED 条目向 OP 展示重试信息 |

逻辑检修覆盖五点。`schedulePolicy` 在同周期重复调用时返回 false，菜单层把 false 翻译为冷却提示并展示下次可操作周期。政策确认页写明 `POLICY_SWITCH_COST` 从国库支出与生效周期，确认回调登记 pending。结算失败置 FAILED 后按 `TAX_WELFARE_RETRY_DELAY_SECONDS` 退避重试，重试次数进入 OP 视图。福利发放后国库低于保护线时按设计文档比例折算，折算比例写入结算摘要消息。推进器在服务器关闭期间错过周期时，重启后按周期标识补算一次，补算与正常推进共用同一幂等键。

验证步骤如下。

1. 政策切换确认后 pending 政策在下一周期到达时生效，同周期第二次切换提示冷却。
2. 注入入账失败场景，结算置 FAILED，延迟后自动重试成功。
3. 重启服务器后错过的周期被补算一次，结算记录不重复。
4. 四子页按身份展示对应内容，成员无法打开汇总页。

逻辑检修覆盖三点。`calculatePlotPrice` 回写 `cachedPrice` 与 `lastPriceRefreshMillis`，菜单打开时读取缓存，管理者手动重算才触发实时计算，打开频率不放大计算量。发展度总值由 `snapshotDevelopment` 的 version 字段标识统计版本，缓存与版本不一致时自动刷新。OP 视图的异常信息来自结算失败原因与重试计数，不向普通成员泄露内部状态。

验证步骤如下。

1. 成员、管理者、OP 打开同一页面看到三档信息密度。
2. 手动重算后 `cachedPrice` 与显示同步更新。
3. 统计版本变化后缓存自动失效。
