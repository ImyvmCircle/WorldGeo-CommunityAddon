# Community V4 前后端落实方案

提交 09a92b5 把 V4 机制的状态层送入仓库，建设奖励台账、地皮、称号、政策、税收福利五个领域模型连同 `CommunityV4Service` 与 `CommunityApi` 入库，玩家侧入口缺位，五个机制没有菜单，税收福利仅有 GM 命令。设计文档 community-main.md 要求社区操作同时具备箱子菜单、可点击消息与命令三类入口，并要求确认页、完整 `runBack` 与按身份过滤的视图。本方案给出菜单树、确认流、消息分层与框架修复清单，覆盖 V4 全部玩家可见路径。

菜单框架现状构成 V4 页面的前置约束。服务端注册 54 个槽位，客户端按 `GENERIC_9x6` 渲染 90 个槽位，玩家点击背包区域时服务端静默忽略，客户端预测与服务端状态分裂，产生幽灵物品与点击失灵的体感。按钮分发依赖物品自定义名匹配，返回逻辑靠逐层透传回调，价格确认长文走聊天栏。新增六个菜单族之前框架缺陷先行修复，V4 页面否则会继承全部既有故障。

## 现状判断

### 值得保留的部分

`entrypoint/screen` 声明槽位、`application/interaction/screen` 承载业务的分层与设计文档一致，新页面沿用同一分工。`AbstractListMenu` 提供分页骨架，`runBack` 全覆盖是既定约定。PendingOperation 注册表具备键控去重、数据库持久化、过期清理与重启恢复，是可点击消息回调的可靠底座。`/_commun` 隐藏命令族承接聊天点击，把回调暴露在普通命令补全之外。成员、管理者、OP 三层身份过滤在既有 handler 中已有实践，新页面沿用同一判断入口。

### 看似完整的老套思路

聊天长文价格确认由 `TerritoryConfirmationMessage.kt` 生成，单次确认输出二十行以上，聊天栏溢出后明细丢失，pending 过期后确认按钮退化为死链，玩家点击后得到一句 `confirmation.not_found`。设计文档给可点击消息的定位是摘要、跳转与通知，完整明细归确认页承载。按钮分发依赖物品自定义名匹配，实现位于 `AbstractMenu.kt:105-106`，名字缺失或重名时按钮静默失灵。手工槽位编排缺乏框架校验，`CommunityMemberListMenu.kt:96-109` 的成员物品覆盖 slot 44 的返回键是结构性后果。`runBack` 逐层透传在页面加深后催生 `runBackGrandfather` 一类命名，续链任何一环断裂即产生死按钮。

### 不切实际的假设

框架假设服务端与客户端槽位集合一致，实际服务端 54 槽、客户端 90 槽，差值 36 槽是背包区点击失灵的来源。框架假设按钮自定义名非空且全局唯一，`PlayerHeadButton.kt:15` 在找不到社区所有者时返回 `ItemStack.EMPTY`，调用方照常注册，槽位退化为无按钮空槽。聊天确认假设玩家会在五分钟 pending 窗口内读完长文并完成点击，聊天被刷走后假设失效。框架假设开菜单的构造函数无副作用，`CommunityMenuOpener.kt:16-20` 在 `getDisplayName()` 内重复调用 `handlerFactory(0)`，每次开菜单构造两个实例，带初始化逻辑的菜单会重复执行初始化。

### 成本过高的方向

引入通用页面栈重写全部菜单收益有限，设计文档要求完整 `runBack`，未要求导航框架，保留手工透传并加框架级非空校验与槽位冲突校验可达到同等可靠性。为每个确认场景编写独立菜单类会造成类膨胀，统一 `ConfirmMenu` 配合 cautions 扩容可覆盖全部场景。菜单内逐 tick 实时刷新地价与发展度浪费带宽，打开时计算加手动刷新按钮足以满足两类页面。

## 菜单树

菜单树沿用既有 `outer_community` 与 `inner_community` 结构，V4 新增六个菜单族。每页注册完整 `runBack`，详情页、确认页、输入页均能回到来源页。

| 页面 | 入口 | 内容 | 确认与回调 | 可见身份 |
| --- | --- | --- | --- | --- |
| 社区总览 | 主菜单、社区列表 | 身份、资产、地皮、政策、成员、公告入口 | 加入申请走聊天确认 | 成员、访客 |
| 资产与国库 | 社区主页 | 余额、捐赠、流水、公共支出 | 捐赠金额确认页 | 成员看摘要，管理者看流水 |
| 地皮市场 | 主菜单、社区主页 | 市场列表、地皮详情、出售、共有确认、扩建申请、审批 | 出售与扩建进确认页，共有操作等对方五分钟 | 所有者、管理者、OP |

## 确认页规范

确认流程统一走 `ConfirmMenu`，cautions 由五条上限扩为 lore 列表，超出部分分页展示。确认页写明影响对象、金额、国库入账方向、权限转换与等待时限，共有出售等待对方五分钟，扩建申请等待管理者一小时，政策切换冷却两周并注明生效周期。价格明细从聊天长文迁入确认页 lore，聊天侧保留摘要行与两个可点击按钮。全部确认回调登记 PendingOperation，携带过期时间、归属校验与重启恢复所需的载荷。玩家点击过期按钮时收到明确提示，提示内附重新发起入口。确认页的取消按钮与 `runBack` 等价，均回到来源详情页。

## 互动消息规范

聊天可点击消息集中到统一构建器，封装 `ClickEvent` 与 `HoverEvent` 样板，必填参数含操作者、社区名、空间名、金额与操作结果，颜色取值走语言资源，`§` 颜色码随之退出。通道按信息量分工，开关状态与领取成功一类短反馈走 action bar，多行说明先关闭菜单再发聊天，危险操作确认留在菜单内。`MainMenuHandler.kt:95-100` 的 deprecated 转发替换为核心模组的 `PlayerInteractionApi.toggleActionBar`。各机制的消息清单按设计文档实现，建设机制发小时结算提醒、扣款失败与统计待重试，地皮机制发挂牌、成交、共有确认、扩建申请与审批结果，税收福利发周结算摘要与折算比例说明，政策机制发切换受理与生效通知。消息按身份过滤，普通玩家看到与自身相关的条目，管理者看到管理动作与审计结果，OP 看到异常与重试状态。

## 框架修复清单

V4 页面开工前完成以下修复，按依赖顺序排列。

1. `AbstractMenu.setupSlots` 增注册玩家背包 36 槽，全部使用 `ReadOnlySlot`，消除 54 与 90 的槽位差，背包区点击引发的幽灵物品随之消失。
2. `AbstractMenu.clicked` 先按 `ContainerInput` 过滤再分发，仅左键拾取触发按钮回调，分发改用槽位索引映射，自定义名匹配退出分发路径。
3. 框架注册背景、返回键与翻页键后校验内容区不占用同一槽位，`CommunityMemberListMenu` 起始槽避让 slot 44。
4. `CommunityMenuOpener` 缓存菜单实例，`getDisplayName()` 复用首次构造结果。
5. 死按钮清理，`CommunityMenu` 成就按钮、`MainMenu` OP 按钮、`ConfirmTaskType` 邀请两个空分支、`TargetSettingMenu` effect 按钮各自补实现或移除。
6. 头颅工厂返回 `ItemStack.EMPTY` 时调用方跳过注册或改用占位物品，空槽按钮随之消失。
7. `AbstractMenu.incrementSlotIndex` 无调用方，移除或接入槽位编排。

## 后端接线

每个 V4 菜单族配一个 application 层 handler，建设、地皮、称号、政策、税收福利各一，权限在菜单层隐藏入口并在 handler 层二次校验。`PendingOperationType` 扩展地皮出售、共有确认、扩建审批、政策切换与限额购买五类，载荷随 `PendingOperation` 数据类追加，数据库字段追加在记录块末尾，旧记录读取时取默认值。周期结算携带 cycle id 保证幂等，失败置 FAILED 进重试队列，离线成员奖励入待处理队列并在上线时发放。跨仓库边界维持现状，空间读写走 `RegionDataApi` 与 `PlayerInteractionApi` 公开入口，金额走 `EconomyMod`，Community 不读 WorldGeo 数据库对象。

## 验收

1. `./gradlew build` 通过。
2. `./gradlew runServer` 实测走查，每个菜单页可进可出，无空槽按钮，背包区点击无幽灵物品，shift 点击无物品移动。
3. 成员、管理者、OP 三种身份分别打开同一页面，入口可见性与信息密度各自匹配身份。
4. 发起地皮出售、共有确认、政策切换各一例，重启服务器后 pending 恢复，过期后点击给出明确提示与重新发起入口。
5. 价格确认页 lore 完整展示明细，聊天摘要在三行以内。
